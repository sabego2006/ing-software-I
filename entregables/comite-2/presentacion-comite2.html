Backend: arquitectura hexagonal

Guía del docente → FusaRoute

GuíaHexagonal
Controlleradapter/in/web/
Serviceapplication/usecase/
Repositoryadapter/out/persistence/

La interfaz del repositorio pertenece al dominio (port/out/), no a la infraestructura. Por eso se puede cambiar de BD sin tocar lógica de negocio. 

com.fusaroute
├── domain
│   ├── model/          Route, User, Fare...
│   ├── exception/      FieldViolation...
│   └── port
│       ├── in/         RegisterUserUseCase...
│       └── out/        UserRepositoryPort...
├── application
│   └── usecase/        RegisterUserService...
└── infrastructure
    ├── config/         SecurityConfig, UseCaseConfig
    └── adapter
        ├── in/web/     AuthController, UserController
        └── out/
            ├── persistence/  JPA entities, repos
            └── security/     BCryptPasswordHasher

Flujo: PUT /api/users/me

Controller → UserController.updateProfile() extrae el sub del JWT
Use Case → UpdateProfileService valida nombre, email, teléfono
Domain → User.updateProfile() crea un User nuevo (inmutable)
Port out → UserRepositoryPort.save() — interfaz en el dominio
Adapter → UserPersistenceAdapter convierte a JPA entity y persiste

¿Por qué dos modelos? User (dominio, puro) ≠ UserJpaEntity (tabla). Un mapper los traduce. Se puede cambiar de BD sin tocar lógica de negocio.

Frontend: Angular 21

Pantallas

RutaAuth
/rutasNo
/rutas/:idNo
/registroNo
/loginNo
/perfilSí (guard)

Zoneless = sin zone.js → signals obligatorios

Interceptor de auth

// NO adjunta token en /api/auth/**
if (req.url.includes('/api/auth/')) {
  return next(req);  // pasa sin Bearer
}

// Adjunta JWT
const token = auth.token();
if (token) {
  req = req.clone({
    setHeaders: { Authorization: `Bearer ${token}` }
  });
}

// 401 fuera de auth → redirige al login
// 401 EN auth → muestra error, NO redirige

Evita que un token vencido en localStorage rompa el registro.
