1. Estudio guiado — El flujo del PUT por dentro

Debes poder contar el recorrido del PUT /api/users/me sin mirar el código. Lee estos archivos en orden:

#ArchivoQué buscar
1 adapter/in/web/UserController.java ¿Qué recibe el PUT? ¿De dónde saca el userId? ¿Qué devuelve?
2 application/usecase/UpdateProfileService.java ¿Qué valida? ¿Cómo crea el User actualizado (inmutable)? ¿Cuándo lanza 409?
3 domain/port/out/UserRepositoryPort.java ¿Por qué es una interfaz en domain/ y no en infrastructure/?
4 adapter/out/persistence/UserPersistenceAdapter.java ¿Cómo traduce del dominio a JPA y viceversa? ¿Qué pasa si cambiamos de base de datos?

El recorrido que debes poder contar (slide 7):

  1. El request entra al controller (@PutMapping)
  2. El controller extrae el userId del JWT (@AuthenticationPrincipal Jwt)
  3. Pasa al use case (UpdateProfileService)
  4. El dominio valida nombre, correo y teléfono, y crea un User nuevo — inmutable
  5. El adaptador de persistencia traduce a JPA y guarda
  6. La respuesta vuelve al controller como DTO
Si el comité pregunta "¿qué pasa si el correo ya existe?", la respuesta es: el servicio consulta existsByEmail, y si existe para otro usuario, lanza una excepción que el advice convierte en 409.

3. Mergear los PR de código

Hay 2 PR en la rama claude/gracious-clarke-2fqs2v de cada repo de código. Tu trabajo es revisar y mergear, no solo aprobar.

Checklist de revisión (6 puntos por PR)

  • CI en verde — si hay checks rojos, no mergear
  • Sin secretos — buscar en el diff: passwords, API keys, tokens, .env con valores reales
  • Sin any (frontend) — buscar la palabra any en archivos .ts del diff
  • ArchUnit / JaCoCo pasan (backend) — verificar en el log del CI
  • Endpoints nuevos documentados en el README — revisar que la tabla de endpoints esté completa
  • Probar la pantalla de perfil — si es posible, desde el portátil de Santiago o desde el preview

Orden de merge:

  1. PR del backend primero (el frontend depende de la API)
  2. PR del frontend después
Mergear no es opcional. La regla "nadie mergea su propio PR" exige que lo hagas tú. Si no lo haces, el código no llega a main y la demo no funciona.
